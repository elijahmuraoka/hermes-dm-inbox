## 1. Executive Summary + Verdict

**Verdict: REQUEST_CHANGES** (expected to clear to APPROVE after the fix batch — all findings are localized).

The build is structurally healthy: typecheck and production build green, zero XSS surface (no
`dangerouslySetInnerHTML`, no `<a href>` anywhere, all content rendered as React text nodes), clean keyboard
listener hygiene, tree-shaken bundle (114KB gzip), and the big v5/v6 view contract (Important/Sent/All
semantics, sort regimes, composer-first lifecycle, diegesis, exit-then-commit) verified faithful to DESIGN.md.

Three Highs block: (H1) typed composer text survives view/filter/sort re-anchoring, so ⌘Enter can mock-send a
reply into the **wrong thread** — the store's own stated invariant ("never let text bleed across
conversations") is enforced on j/k paths but not the five re-anchor paths; (H2) count honesty breaks under
filters — rail counts, list-title counts, and the "Show done (n)" count each use a different filter lens,
violating the in-code F1 claim and DESIGN's honest-count rule; (H3) the light-theme AA retune darkened
`--primary` but left four sibling tokens (`--view-important`, `--status-unread`, `--sidebar-primary`,
`--glow-primary`) at the old blue, splitting the ONE-accent rule, and DESIGN §1's published palette is stale
against the code.

## 2. Findings by severity

### 🔴 Critical
None.

### 🟠 High

**H1 — Composer text bleeds across conversations on re-anchor; can mock-send to the wrong person.**
- Location: `apps/web/src/hooks/useInboxStore.ts:223-227` (`setView`), `:727-735` (`applyFilters`),
  `:239-243` (`setSortMode`), `:245-251` (`toggleShowDone`), `:255-268` (`toggleSection`)
- Why: type a reply to Dana in Important, press `g a` (or click a filter chip / change sort) → selection
  re-anchors to a different conversation with the typed text still in the composer; ⌘Enter appends it to the
  wrong thread and flips it to sent (wrong-data mutation). The invariant stated at `:284-285` is enforced in
  `selectNext`/`selectPrev`/`selectId`/`advanceSelection` but not these five paths.
- Fix: extract one re-anchor helper that clears `composerText`/`composerAttach` whenever `selectedId`
  changes (same shape as `advanceSelection` at `:785`); use it at all five sites.

**H2 — Count honesty breaks under filters: rail vs title vs "Show done (n)" use three different lenses.**
- Location: `apps/web/src/components/ViewNav.tsx:26-40` (source-lens only) vs
  `apps/web/src/components/ConversationList.tsx:47-50` (full-filter population) vs `:54-57`
  (`doneCount` — no lens at all); stale claim at `ConversationList.tsx:86-88` ("title count always agrees
  with the rail (F1)")
- Why: with Unread/person/draft filters active the rail says 12 while the title says 3; with a source chip
  active "Show done (5)" can reveal 1 row. Counts are this product's trust mechanism by explicit contract
  (DESIGN §3: "honest count, nothing silently disappears"); this is the F1/F3 defect class recurring.
- Fix: one shared `population(conversations, view, filters, now)` helper in `derive.ts`, used by rail counts,
  title count, and done-toggle count under the same active-filter lens.

**H3 — Light-theme accent tokens split after the AA retune; DESIGN §1 palette stale against code.**
- Location: `apps/web/src/index.css:23` (`--primary: oklch(0.48 0.16 245)`) vs `:49,:55,:37,:61`
  (`--view-important`, `--status-unread`, `--sidebar-primary`, `--glow-primary` still `oklch(0.55 0.15 235)`);
  dark: `:100` `--urgency-high` ≠ `--destructive` (`:80`) where DESIGN §3 says they're equal; DESIGN.md §1
  palette blocks carry pre-retune values.
- Why: two different blues both act as "the ONE accent" in light mode (scalpel rule violated); the living
  contract now disagrees with the code, so the next generation pass against DESIGN.md would reintroduce the
  pre-AA values.
- Fix: define sibling tokens as `var(--primary)` / `var(--destructive)`; update DESIGN §1 in the same commit.

### 🟡 Medium

**M1 — `sendMock` leaves selection orphaned; next `j` yanks to the top of the list.**
`useInboxStore.ts:644-706` has no `advanceSelection`/`beforeIdx` capture, unlike `markDone` (`:322-349`) which
fixed exactly this. After send from mid-list, `selectNext` (`:279-287`) `findIndex === -1` → row 0. Fix: capture
`beforeIdx` and make orphaned-selection fallback use the nearest index, not 0.

**M2 — Reading a thread never clears `unread`.** Only `markDone`/`sendMock` clear it
(`useInboxStore.ts:329,334,659,672`); opening a thread doesn't (`:298-306`). Dot, rail badge, and Unread filter
treat a fully-read FYI as unseen forever. Every reference inbox clears on open. Fix (taste call, decided):
clear `unread` in `selectId`/`openThread`.

**M3 — `e` mid-draft-flow archives the thread and destroys the draft.** `useKeyboard.ts:88-91`: only
`generated`/`iterated` route `e` to add-to-chat; `requested`/`angles_ready`/`added_to_chat` fall through to
`markDone()` — a one-key slip in the hero loop destroys in-progress work. BACKLOG's own rule: "on a drafted
thread `e` = add-to-chat wins over archive." Fix: treat `requested`/`angles_ready` as in-draft (no-op or focus
angles); archive requires its dedicated path once a draft exists.

**M4 — Esc while typing in the sheet's studio input burns two layers.** `useKeyboard.ts:29-38` handles Escape
before the `isTyping` guard (`:41`); the textarea's blur-on-Esc (`HermesDraftPanel.tsx:342-344`) doesn't
`stopPropagation`, so below xl one press blurs AND closes the sheet, losing the typed instruction. Fix: in the
global Escape branch, return after blur when `isTyping(e.target)`.

**M5 — Two of three aria-modal dialogs have no focus management.** `ShortcutSheet.tsx:52-58` (role=dialog,
aria-modal, no focus move-in/trap/restore), `CommandPalette.tsx:361-368` (autofocus but no Tab trap);
`MobileDrawer` (`App.tsx:166-199`) hand-rolls it correctly. Contract §7 / DESIGN §8.8 promise full keyboard
operability. Fix: extract MobileDrawer's trap into `useFocusTrap(ref)` and apply to all three.

**M6 — `setComposerText` rewrites the whole `conversations` array on every keystroke once a draft diverges.**
`useInboxStore.ts:593-610`: after add-to-chat + first edit, every keystroke maps 48 conversations to rewrite
`status: "edited"` to itself → whole-app re-render per keystroke (list derives twice, ViewNav 7 count passes,
palette useMemo). Milliseconds at 48 fixtures; the exact render-storm shape at real scale. Fix: only write on
the actual `added_to_chat → edited` transition.

**M7 — `requestDraft` unguarded: double-`d` schedules duplicate timers; `d` mid-draft degrades the lifecycle.**
`useInboxStore.ts:409-454` guards only `exitingIds`; `d` on `added_to_chat`/`edited` resets the status chain so
divergence tracking and `fromHermes` attribution silently break (`:598-601`, `:649-651`), leaving a stale draft
chip after send. Fix: early-return when status is `requested`/`angles_ready`/`added_to_chat`/`edited`.

**M8 — Mock-Hermes brain (~150 lines of pure logic) lives unexported inside the 905-line store hook.**
`useInboxStore.ts:169-178, 795-905` (`suggestPostSend`, `MOCK_ANGLE_SETS`, `anglesFor`, `applyInstruction`) —
the fragile ask-vs-closer precedence and shorten-guard logic is untestable in place while `lib/derive.ts` shows
the clean pattern. Fix: extract to `lib/mock-hermes.ts` (also the primary test seam). *Deferred to BACKLOG with
the testing note below if not taken in this batch.*

## 4. Security Summary (OWASP-aligned, static SPA scope)

No exploitable surface today: no XSS sinks (A03) — verified zero `dangerouslySetInnerHTML`/`innerHTML`/href
rendering; no auth/session to attack (mock, local-first); localStorage usage is try/catch-guarded UI prefs
(theme, hint, fold) with strict comparisons — no injectable sink. Future-facing (when real DM data lands):
L7 (untrusted sender ids → crash = availability), L6 (`?state=` demo spoofing on a deployed URL), CSP absent
(L18). No secrets in the diff; `vite.config.ts` binds 127.0.0.1 with strictPort, matching the local-first
invariant.
